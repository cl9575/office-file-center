### 默认端口调整

- 部署主机上 `8443` 已被其他程序占用，浏览器打开该端口时出现的是其他程序的 HTTP Basic 登录弹窗，而不是本平台页面。
- 正式默认端口统一调整为 `9443`：程序默认参数、安装/卸载脚本、证书信任脚本、页面提示和全部文档均已同步；安装时仍可填写其他空闲端口。
- 上述发布包验证使用 `8597` 完成，说明安装脚本可正确适配任意端口。
- 端口调整后已重新构建发布包；`go test ./...` 通过，并以默认参数启动确认 `https://localhost:9443/api/setup/status` 返回初始化状态。

### 证书信任与密码规则验证

- 自动证书改为“本地根证书 + 服务器证书”：根证书有效期 10 年；服务器证书由根证书签发，有效期 2 年，SAN 覆盖当前主机名、回环和全部网卡 IP。
- 主机 IP 或主机名变化时自动重签服务器证书，根证书不变；自动化测试验证根证书指纹保持不变、服务器证书包含新增主机名。
- 发现并修复：Windows PowerShell 5.1 设置 `ServerCertificateValidationCallback` 后，`Invoke-WebRequest` 对任何 HTTPS（包括公网）都报“连接被意外关闭”。信任脚本改用 Windows 自带 `curl.exe` 下载根证书和服务器证书，并新增 `/api/server-cert` 供核对 SAN。
- `trust-certificate.ps1 -VerifyOnly` 在 `https://localhost:9444` 和 `https://192.168.2.124:9444` 实测通过，能正确识别访问地址是否在 SAN 中。
- 实际导入根证书后，脚本内 `X509Chain` 验证通过；Chromium 浏览器打开 `https://localhost:9444` 直接进入登录页，无证书警告。测试后已从当前用户受信任根存储移除测试证书并确认无残留。
- 发布包新增单文件「一键信任证书.cmd」：直接运行即可完成证书下载、SAN 核对、根证书导入和证书链验证，无需手动输入命令；默认仅为当前用户安装，以管理员身份运行时为所有用户安装。对 `https://127.0.0.1:9455` 实测退出码 0，对未监听的 9456 端口实测退出码 1 且未写入证书；测试后已从当前用户和本地计算机受信任根存储移除测试证书并确认无残留。
- 密码最小长度改为 6 位：5 位密码初始化返回失败，6 位密码初始化成功；前端表单提示同步为 6 位。

- 手动备份包含一致性快照、清单、完成标记和对象内容；对象 SHA-256 与清单一致。
- 每次成功备份额外生成 `files/` 可读副本：按原文件夹和文件名保存当前版本，可直接在资源管理器打开；历史版本仍保存在 `objects/` 和 `meta.db` 中。

- 使用正式二进制执行：

```powershell

```

  恢复成功，目标包含 `meta.db` 和对象文件；集成测试进一步打开恢复后的数据库并确认文件名和对象内容。
- 恢复目标非空时会拒绝，未完成备份不能恢复。
