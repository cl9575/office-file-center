# 管理员部署指南

本文面向负责安装和维护办公室文件中心的管理员。按照顺序完成即可。

## 1. 部署前准备

### 主机要求

- Windows 10 / 11 专业版、企业版，或 Windows Server 2019 及以上，64 位。
- 建议 4 核 CPU、8 GB 内存、SSD 系统盘。
- 长期开机、使用有线千兆网络，关闭睡眠和休眠。
- 设置固定 IP，或在路由器中为该主机保留 DHCP 地址。员工访问地址会随 IP 改变，证书也需要重新生成。
- 主机只用于本系统更稳定；与办公电脑兼用时，关机期间员工无法访问。

### 容量估算

版本库会为每次更新保存一份完整文件内容（恢复历史版本时复用未变化的对象），因此不能只按当前文件量购买硬盘。

估算公式：

```text
需要容量 ≈ 当前文件总量 × (1 + 平均保留历史份数) + 增长余量
```

例如当前 100 GB、平均每个文件保留 4 个历史版本，文件内容约需 500 GB；再加数据库、临时上传、系统保留空间，建议至少 1 TB，备份空间另算。

### 网络与防火墙

- 办公室网络配置文件应为“专用”或“域”，不要使用“公用”。
- 安装脚本只开放 TCP 端口的**本地子网**访问，不向公网开放。
- 不要把端口转发到互联网，也不要放在无防护的公网服务器上。

### 备份目标

准备一块独立的移动硬盘、另一块内置硬盘，或另一台电脑上的共享目录。备份目标可与数据盘同机，但无法抵御整机损坏；最理想是另一台设备。

## 2. 安装

1. 将发布包 `LanFilePlatform-0.2.1.zip` 解压到主机。
2. 双击 `安装.cmd`，在 Windows 提示时选择“是”以管理员权限运行。
3. 按提示确认：
   - 数据目录，默认 `D:\LanFileData`（可以改为其他独立磁盘路径）。
   - 访问端口，默认 `9443`。`8443` 等端口常被其他软件占用；如果安装时提示端口已被占用，换一个空闲端口（例如 `9443`、`10443`）即可，员工访问时使用对应的新端口。
4. 脚本会自动：
   - 安装程序到 `C:\Program Files\LanFilePlatform`；
   - 把数据目录权限授予低权限服务账号 `NT AUTHORITY\LocalService`；
   - 添加入站防火墙规则（专用/域网络、本地子网、指定 TCP 端口）；
   - 注册并启动 Windows 服务 `LanFilePlatform`，设置为自动启动；
   - 配置服务失败后自动重启；
   - 自动打开本机访问地址。

安装完成后可检查：

```powershell
Get-Service LanFilePlatform
sc.exe qc LanFilePlatform
```

### 覆盖升级（保留原有数据）

1. 先在「管理后台 → 备份与系统」做一次手动备份，或复制一份数据目录。
2. 解压新版本发布包，双击 `安装.cmd`。
3. 提示填写**数据目录**和**端口**时，必须保持与原安装一致（常见为 `D:\LanFileData`、`9443`），否则新服务会指向一个空目录。
4. 安装脚本只停止并重建服务、替换 `C:\Program Files\LanFilePlatform` 下的程序文件；数据目录中的数据库、历史文件、备份和日志不会被删除或覆盖。

升级完成后用原管理员账号登录即可。若升级前修改过安装目录或服务名，请用相同参数运行 `install.ps1`。

日志：`<数据目录>\logs\server.log`。日志按 10 MB 轮转，保留 3 份历史文件。

## 3. 首次初始化

1. 在**主机上**打开 `https://localhost:9443`。
2. 浏览器提示证书不受信任时，选择“高级 → 继续访问”。这是首次使用自签名证书的正常提示。
3. 创建初始管理员：用户名（3～32 位字母/数字/下划线/点/短横线）、显示名称、至少 6 位密码。
4. 登录后进入“管理后台”：
   - “用户管理”创建同事账号，分配管理员、编辑者或只读者角色；
   - “系统设置”修改平台名称、单文件上限、备份策略；
   - “备份与系统”确认 HTTPS、存储空间和备份状态。

初始化入口只允许从主机本机访问；初始化完成后该入口自动关闭。系统没有通用默认密码。

初始化时创建的账号会成为**主机账号**：固定为管理员，不能降级或停用，只能由本人维护显示名称和密码。其他管理员不能编辑或重置该账号，服务端会拒绝相关请求。请妥善保管主机账号的密码。

## 4. 员工电脑接入

平台本身不需要安装客户端，但 HTTPS 证书需要每台电脑一次性信任，否则浏览器会显示安全警告，并且不一定允许登录。

系统使用“本地根证书 + 服务器证书”的方式：员工电脑只需信任一次本地根证书；以后主机 IP 或主机名变化，服务器会自动重签服务器证书，员工电脑**不需要重新导入**。

### 方法一：证书信任脚本（推荐）

最简单的方式：把发布包或安装目录中的 `一键信任证书.cmd` 发给员工，双击运行即可。

- 双击：仅为当前 Windows 用户安装，不需要管理员权限；
- 右键“以管理员身份运行”：为这台电脑的所有 Windows 用户安装；
- 窗口显示“证书链验证：通过”后按任意键关闭，再完全退出并重开浏览器。

文件默认连接 `https://192.168.1.100:9443`。如果主机地址或端口变了，用记事本打开文件，修改开头的 `set "SERVER=..."` 一行，或使用新版发布包中的文件。

如果习惯命令行，或需要批量部署和排查，也可以使用下面的 PowerShell 命令：

在员工电脑上打开 PowerShell（当前用户即可，不需要管理员）：

```powershell
powershell -ExecutionPolicy Bypass -File .\trust-certificate.ps1 -Server https://192.168.1.100:9443
```

如果希望该电脑的所有 Windows 用户都信任，使用管理员 PowerShell：

```powershell
powershell -ExecutionPolicy Bypass -File .\trust-certificate.ps1 -Server https://192.168.1.100:9443 -Machine
```

脚本会：

1. 从服务器下载根证书；
2. 连接服务器，检查实际下发的服务器证书是否包含本次访问的 IP 或主机名；
3. 把根证书导入 `Cert:\CurrentUser\Root`（`-Machine` 时为 `Cert:\LocalMachine\Root`）；
4. 验证服务器证书链，并打印证书指纹和 SAN 地址。

看到“证书链验证：通过”后，**必须完全退出所有 Edge/Chrome 窗口**（包括后台进程）再重新打开。可以直接在地址栏访问 `edge://restart` 或 `chrome://restart` 重启浏览器。只刷新页面可能仍显示旧警告。

如果导入前想先检查服务器证书是否正确，可加 `-VerifyOnly`（只验证、不导入）：

```powershell
powershell -ExecutionPolicy Bypass -File .\trust-certificate.ps1 -Server https://192.168.1.100:9443 -VerifyOnly
```

### 方法二：手动导入

管理员在“管理后台 → 备份与系统 → HTTPS 证书”点击“下载客户端证书”，把 `.cer` 文件发给员工：

1. 双击 `.cer` →“安装证书”；
2. 选择“当前用户”→ 下一步；
3. 选择“将所有的证书都放入下列存储”→ 浏览 →“受信任的根证书颁发机构”；
4. 完成导入后完全退出并重开浏览器。

也可以在员工电脑执行：

```powershell
certutil -user -addstore Root .\office-files-cert.cer
```

### 核对指纹

在员工电脑导入前，与管理员后台显示的 **SHA-256 指纹**核对一致。这里显示的是根证书指纹，`trust-certificate.ps1` 打印的也是根证书指纹。不要把来源不明的证书导入受信任存储。

### 地址变化

- 主机 IP 或主机名变化：管理员只需重启服务，系统检测到服务器证书缺少新地址后会自动重签服务器证书。员工电脑继续信任原根证书，**无需重新导入**。
- 只有删除 `<数据目录>\certs` 或更换根证书时，员工电脑才需要重新执行信任脚本。
- 建议仍给主机设置固定 IP 或 DHCP 地址保留。

### 仍然显示安全警告时

1. 确认浏览器地址与脚本打印的 SAN 完全一致，例如必须是 `https://192.168.1.100:9443`，不能混用另一块网卡的 IP。
2. 完全退出所有 Edge/Chrome 窗口后重开，或访问 `edge://restart` / `chrome://restart`。
3. 用 `-VerifyOnly` 检查服务器证书是否包含当前访问地址；如果缺少，停止并重新启动服务让服务器重签证书。
4. 确认根证书在当前用户存储中：

```powershell
Get-ChildItem Cert:\CurrentUser\Root | Where-Object { $_.Subject -like "*办公室文件中心*" }
```

5. 如果使用 Firefox，需要在 Firefox 自己的证书设置中导入，Windows 证书存储对它无效。
6. 仍无法解决时，把脚本完整输出、浏览器显示的证书详情和管理员后台的指纹一起提供给维护人员。

> 从旧版本升级后第一次启动会生成新的根证书，员工电脑需要重新导入一次；之后 IP 变化不再需要。

### 使用企业内部证书（可选）

如果单位已有受信任的证书或内部 CA，可不使用自动证书。准备 PEM 格式证书和私钥，授予 LocalService 读取权限，然后修改服务启动参数：

```powershell
Stop-Service LanFilePlatform
icacls "D:\Certs" /grant "*S-1-5-19:(OI)(CI)RX" /T

$bin = '"C:\Program Files\LanFilePlatform\LanFileServer.exe" -data "D:\LanFileData" -addr ":9443" -tls-cert "D:\Certs\server.crt" -tls-key "D:\Certs\server.key"'
Get-CimInstance Win32_Service -Filter "Name='LanFilePlatform'" |
    Invoke-CimMethod -MethodName Change -Arguments @{ PathName = $bin }

Start-Service LanFilePlatform
```

证书必须包含员工实际访问的主机名或 IP。企业内部证书由单位 CA 签发时，员工电脑通常已信任，不需要单独导入。

### 只做本机测试

临时测试可以使用明文模式：

```powershell
LanFileServer.exe -data D:\LanFileTest -addr :8080 -http
```

HTTP 模式下密码和文件不加密，**不得用于正式办公室环境**。

## 5. 账号和权限

| 角色 | 浏览/搜索/下载 | 上传、更新、改名、移动、删除 | 历史恢复 | 回收站恢复/永久清理 | 账号与系统管理 |
|---|---|---|---|---|---|
| 管理员 | 是 | 是 | 是 | 是 | 是 |
| 编辑者 | 是 | 是 | 是 | 否 | 否 |
| 只读者 | 是 | 否 | 否 | 否 | 否 |

- 新账号首次登录必须修改初始密码。
- 管理员重置密码后，该账号已有登录会失效，下次登录仍需改密。
- 停用账号会立即使其会话失效；历史操作记录保留。
- 系统禁止停用或降级最后一个可用管理员。
- 初始化时创建的账号标记为“主机账号”，只能由本人维护；其他管理员不能修改其资料、角色、状态，也不能重置其密码。
- 只有主机账号可以删除其他账号；主机账号不能删除自己。删除后账号立即无法登录，但已上传文件、历史版本和操作记录会保留。若只是暂时停用，请优先使用“编辑 → 停用账号”。

## 6. 备份（必做）

历史版本保存在同一块数据盘上，**不能防止硬盘损坏、主机丢失或勒索软件**。

### 配置

1. 准备独立备份目录，例如 `E:\OfficeBackup` 或另一台电脑的共享目录。
2. 如果备份目录在本地磁盘，确保 LocalService 有写权限：

```powershell
icacls "E:\OfficeBackup" /grant "*S-1-5-19:(OI)(CI)M" /T
```

3. 管理员登录 →“系统设置”：
   - 启用每日自动备份；
   - 设置每天开始时间和保留成功备份份数；
   - 填写备份目录，保存。
4. 打开“备份与系统”，点击“立即备份”，确认出现“成功”记录。

注意：`NT AUTHORITY\LocalService` 默认不能使用带密码的网络共享。若必须备份到 NAS，建议使用本地外置硬盘，或请 IT 人员把服务改为有网络访问权限的专用本地账号。服务账号变更需重新授予数据目录和备份目录权限。

### 备份内容

每个成功备份目录包含：

```text
run-YYYYMMDD-HHMMSS/
├── meta.db          数据库一致性快照
├── manifest.json    数据库摘要和全部对象清单
├── complete.json    完成标记
├── objects/         全部版本文件内容（含回收站）
├── files/           当前版本的可读副本（原文件夹、原文件名，可直接打开）
├── README-可读副本.txt
└── certs/           自动根证书与服务器证书（ca.crt/ca.key/server.crt/server.key）
```

`files/` 是方便直接用资源管理器查看的副本，只包含**当前版本**；历史版本仍完整保存在 `objects/` 和 `meta.db` 中。为兼容 Windows，极少数与系统保留名冲突的名称会加上前缀。可读副本会额外占用约等于当前文件总量的备份空间。它只用于应急查看，完整恢复仍应使用 `-restore`。

备份通过 SQLite 在线快照创建，不是简单复制正在使用的数据库文件。每个复制对象都重新计算 SHA-256 并校验；只有全部成功才写入完成标记。失败备份不会覆盖上一份成功备份。

备份中的 `certs` 目录包含根证书私钥；泄露后可能被用来伪造受员工电脑信任的站点，必须和业务数据同等保护。

### 保留与风险

- 默认保留最近 7 份成功备份，可在系统设置调整。
- 备份目录不要放在数据目录内，系统会拒绝这种配置。
- 自动备份只在设定的那一分钟触发；如果主机当时关机，当天不会自动补做。请查看“最近成功”时间，必要时手动备份。
- 每日一次备份意味着最坏情况下可能丢失约 24 小时内的新修改。重要项目可随时手动备份。
- 备份目录包含全部文件和服务器私钥，应像业务数据一样限制访问。为防止勒索软件加密备份，建议定期轮换一块离线移动硬盘。

### 恢复演练（至少每季度一次）

不要直接在生产目录上练习。使用独立空目录启动一个临时实例：

```powershell
# 1. 选择一个完整备份目录
$backup = "E:\OfficeBackup\run-20261113-023000"

# 2. 恢复到空目录（目标必须为空）
& "C:\Program Files\LanFilePlatform\LanFileServer.exe" -restore $backup -restore-to "D:\RestoreCheck"

# 3. 临时启动并核对
& "C:\Program Files\LanFilePlatform\LanFileServer.exe" -data "D:\RestoreCheck" -addr ":8444" -http
```

打开 `http://localhost:8444`，核对账号、目录、当前文件、历史版本和回收站。核对完成后关闭临时实例，再删除 `D:\RestoreCheck`。

`-restore` 会校验数据库摘要和每个对象，不会接受未完成的备份。

### 真实故障恢复

1. 停止服务：`Stop-Service LanFilePlatform`。
2. 保留现场，不要删除旧数据。把 `D:\LanFileData` 改名为 `D:\LanFileData.bad-20261113`。
3. 新建空目录 `D:\LanFileData`，用备份恢复：

```powershell
& "C:\Program Files\LanFilePlatform\LanFileServer.exe" -restore "E:\OfficeBackup\run-..." -restore-to "D:\LanFileData"
icacls "D:\LanFileData" /grant "*S-1-5-19:(OI)(CI)M" /T
```

4. 启动服务，确认文件历史后可继续使用。
5. 如果恢复失败，停止服务，将 `D:\LanFileData` 改名为其他名字，把 `D:\LanFileData.bad-...` 改回原名，再联系技术人员。不要覆盖旧数据直到确认恢复成功。

若使用外部证书（`-tls-cert/-tls-key`），证书文件不在数据目录中，恢复后需单独放回原路径。

## 7. 日常维护

- 每天或每周查看“备份与系统”：服务是否正常、磁盘剩余空间、最近成功备份时间。
- 上传因空间不足暂停时：清理无用的回收站内容或经确认后清理历史版本，或扩容磁盘。不要手工删除 `objects` 文件。
- 回收站可在“管理后台 → 回收站”逐项永久删除，或点击“清空回收站”一键全部永久删除；两者都不可撤销，操作会记入日志。
- 员工离职：优先停用账号，不删除账号，保留历史记录；如需彻底移除误建账号，可由主机账号在用户管理中删除，历史记录仍会保留。
- 版本增长过快时：在文件详情的历史版本页，由管理员逐个清理不需要的旧版本；操作会记入日志。
- 定期检查主机 Windows 更新、磁盘健康和 UPS/供电。
- 重启主机前可在服务管理器中停止服务；服务本身支持优雅停止，正常重启不必手工操作。

## 8. 升级

1. 先完成一次手动备份，并确认成功。
2. `Stop-Service LanFilePlatform`。
3. 保留旧版程序文件或整个发布包。
4. 用新版 `LanFileServer.exe` 覆盖程序目录（不要覆盖数据目录）。
5. `Start-Service LanFilePlatform`。数据库迁移会自动执行。
6. 登录验证文件、历史、账号和备份。

也可以直接双击新版包中的 `安装.cmd` 完成升级：脚本会停止并删除旧服务、覆盖程序文件，再按提示的数据目录和端口重新注册并启动，数据目录内容不会被删除。提示数据目录和端口时必须填写**与原安装相同**的值（默认 `D:LanFileData`、`9443`，当初未改过就直接回车）；填错会指向空目录，看起来像数据丢失。升级前同样要先做备份，并保留旧发布包以便回退。

从旧版本升级时，迁移会把现有的**最早活动管理员**标记为唯一主机账号。升级后请在“用户管理”中确认主机账号标识，并妥善保管该账号密码。

如果新版启动失败，停止服务，换回旧版程序，并用升级前备份恢复数据库。**不要用旧版程序直接读取已经升级过的新版数据库。**

## 9. 故障排查

| 现象 | 排查 |
|---|---|
| 服务无法启动 | 查看 `<数据目录>\logs\server.log`；检查端口是否被占用；确认数据目录 ACL 含 LocalService 权限；`sc.exe query LanFilePlatform` 查看退出码 |
| 员工无法打开页面 | 主机是否开机；地址和端口是否正确；网络是否为专用/域；防火墙规则是否存在；从主机本机 `https://localhost:9443` 是否可用 |
| 浏览器证书警告 | 该电脑未导入证书，或主机 IP 变化导致证书不匹配；重新下载/导入并核对指纹 |
| 能打开但登录失败 | 密码错误、账号停用、连续失败被临时限速（5 分钟后重试）；管理员可重置密码 |
| 首次初始化按钮提示不能操作 | 必须从主机本机 `localhost`/`127.0.0.1` 访问 |
| 上传提示空间不足 | 检查数据盘剩余空间和“保留空间”设置；系统会保留一定空间保障服务运行 |
| 上传提示版本冲突 | 文件已被他人更新；刷新页面查看最新版本，再决定重新上传或改名 |
| 备份失败 | 备份目录不存在/无写权限/磁盘满/源文件缺失；查看备份记录中的具体消息和日志 |
| 备份显示“进行中”但服务重启过 | 启动时会把中断任务标记为失败；重新手动备份即可 |
| 下载文件 404 | 文件可能已被删除或数据对象缺失；检查回收站和日志，必要时从备份恢复 |
| 忘记管理员密码 | 普通管理员可由其他管理员重置；主机账号只能由本人登录后修改密码。若主机账号也忘记，需要技术人员直接操作数据库，暂无自助重置命令 |

## 10. 安全注意事项

- 正式环境必须使用 HTTPS；不要长期使用 `-http`。
- 每台主机和员工账号使用独立密码，不要共用管理员账号。
- 不把服务暴露到互联网；不在公用网络配置文件下开放端口。
- 服务使用 LocalService 运行，数据目录权限只授予该账号和必要管理员。
- 操作日志能追溯日常操作，但主机管理员可直接修改本地文件，因此不是防篡改审计系统。
- 平台不运行上传的文件内容，但不替代杀毒软件；员工下载后仍需终端安全防护。
- 备份目录与服务器私钥应限制访问；重要环境使用离线副本防勒索软件。
- 自签名证书只适合内部使用；具有内部 CA 时优先使用 CA 签发的证书。
