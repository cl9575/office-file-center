# 管理员部署指南

本文面向负责安装和维护办公室文件中心的管理员。按照顺序完成即可。

> 适用产品版本：**0.4.1**；文档修订日期：**2026-11-26**。本文按当前源码整理，不代表本轮已部署或完成现场验证。正式主机仅有 **0.1.0 的旧记录**，本轮未现场核验；历史测试不能替代当前主机验收。文中地址、路径和服务名为示例或默认值，执行前须核对实际配置。

## 1. 部署前准备

### 主机要求

- Windows 10 / 11 专业版、企业版，或 Windows Server 2019 及以上，64 位。
- 建议 4 核 CPU、8 GB 内存、SSD 系统盘。
- 长期开机、使用有线千兆网络，关闭睡眠和休眠。
- 设置固定 IP，或在路由器中为该主机保留 DHCP 地址。IP 变化后应更新员工访问地址，并安排重启服务，让自动证书在启动时检查、补齐新地址；不是运行中自动监控。
- 主机只用于本系统更稳定；与办公电脑兼用时，关机期间员工无法访问。

### 容量估算

版本库会为每次更新保存一份完整文件内容（恢复历史版本时复用未变化的对象），因此不能只按当前文件量购买硬盘。

估算公式：

```text
需要容量 ≈ 当前文件总量 × (1 + 平均保留历史份数) + 增长余量
```

例如当前 100 GB、平均每个文件保留 4 个历史版本，文件内容约需 500 GB；再加数据库、临时上传、系统保留空间，建议至少 1 TB，备份空间另算。

### 网络与防火墙

- 办公室网络配置文件应为“专用”或“域”，不要使用“公用”。
- 安装脚本只开放 TCP 端口的**本地子网**访问，不向公网开放。
- 不要把端口转发到互联网，也不要放在无防护的公网服务器上。

### 备份目标

准备一块独立的移动硬盘、另一块内置硬盘，或另一台电脑上的共享目录。备份目标可与数据盘同机，但无法抵御整机损坏；最理想是另一台设备。

## 2. 安装

1. 将发布包 `LanFilePlatform-0.4.1.zip` 解压到主机。
2. 双击 `安装.cmd`，在 Windows 提示时选择“是”以管理员权限运行。
3. 按提示确认：
   - 数据目录，默认 `D:\LanFileData`（可以改为其他独立磁盘路径）。
   - 访问端口，默认 `9443`。`8443` 等端口常被其他软件占用；如果安装时提示端口已被占用，换一个空闲端口（例如 `9443`、`10443`）即可，员工访问时使用对应的新端口。
4. 脚本会自动：
   - 安装程序到 `C:\Program Files\LanFilePlatform`；
   - 把数据目录权限授予低权限服务账号 `NT AUTHORITY\LocalService`；
   - 添加入站防火墙规则（专用/域网络、本地子网、指定 TCP 端口）；
   - 注册并启动 Windows 服务 `LanFilePlatform`，设置为自动启动；
   - 配置服务失败后自动重启；
   - 自动打开本机访问地址。

安装完成后可检查：

```powershell
Get-Service LanFilePlatform
sc.exe qc LanFilePlatform
```

### 覆盖升级（保留原有数据）

1. 在线时优先在「管理后台 → 备份与系统」做一次手动一致性备份并确认成功。若选择复制数据目录，**必须先停服，确认所有使用该目录的服务及临时进程均已退出、无进程占用后，再完整冷拷贝整个数据目录**（含数据库及伴随文件、`objects`、`certs` 等）。禁止只复制运行中的 `meta.db`。
2. 常规安装优先解压新版发布包后双击 `安装.cmd`，填写与原安装一致的数据目录和端口（默认 `D:\LanFileData`、`9443`），不要把默认值误当成现场配置。
3. 升级前须记录并沿用全部自定义配置；自定义安装目录、服务名、服务账号、证书及其他启动参数的处理，以及验证和回滚步骤，统一见[第 8 节：升级](#8-升级)。安装脚本不删除数据目录，但新版首次启动会执行数据库迁移，不能据此省略备份。
4. 0.3.0 首次启动会追加 `005_operator_role.sql` 和 `006_secure_zone.sql`：加入操作员角色、权限区空间和文件可见性。迁移 005 会重建用户表并清空会话，**升级后所有用户需要重新登录**；迁移 006 会自动创建“权限区”根节点。0.4.1、0.4.0、0.3.3、0.3.2、0.3.1-r2、0.3.1 与 0.3.0 数据库结构相同、没有新增迁移；0.4.1 仅调整重命名后缀校验。从 0.2.8 及更早升级必须先做完整备份并保留匹配旧包；回滚时不能直接用旧程序打开已迁移的数据库。0.4.0 的浏览器预览从现有对象读取，不生成公开静态副本，也不替代备份或终端安全软件。

日志：`<数据目录>\logs\server.log`。当前实现只在**程序启动时**检查已有日志是否大于 `10 MiB`（`10 × 1024 × 1024` 字节），超过才轮转，最多保留 `.1`～`.3` 三份历史文件。运行中持续追加，**不会到 10 MB 就自动轮转或限额**，须巡检日志增长和磁盘余量。

## 3. 首次初始化

1. 在**主机上**打开 `https://localhost:9443`。
2. 浏览器提示证书不受信任时，选择“高级 → 继续访问”。这是首次使用自签名证书的正常提示。
3. 创建初始管理员：用户名（3～32 位字母/数字/下划线/点/短横线）、显示名称、至少 6 位密码。
4. 登录后进入“管理后台”：
   - “用户管理”创建同事账号，分配管理员、操作员、编辑者或只读者角色；只有主机账号能授予管理员，普通管理员最高只能创建或调整为操作员；
   - “系统设置”修改平台名称、单文件上限、备份策略；
   - “备份与系统”确认 HTTPS、存储空间和备份状态。

初始化入口只允许从主机本机访问；初始化完成后该入口自动关闭。系统没有通用默认密码。

初始化时创建的账号会成为**主机账号**：固定为管理员，不能降级或停用，只能由本人维护显示名称和密码。其他管理员不能编辑或重置该账号，服务端会拒绝相关请求。请在受控位置妥善保管主机账号凭据，不写入随包文档。主机账号遗失密码时没有自助恢复入口或命令；应由授权技术人员先在隔离副本验证恢复方案，经确认后再安排正式处理，不要临时直接修改生产数据库。

## 4. 员工电脑接入

平台本身不需要安装客户端，但 HTTPS 证书需要每台电脑一次性信任，否则浏览器会显示安全警告，并且不一定允许登录。

系统默认使用“本地根证书（CA）+ 服务器证书”的方式。**自动证书和 CA 的有效性检查发生在程序启动时，不是运行中监控或自动热更新**：服务器证书缺失、无效、密钥不匹配、签名不符、剩余有效期不超过 30 天或缺少所需地址时会重签；根 CA 缺失、无效、密钥不匹配或剩余有效期不超过 1 年时会重建。员工电脑在根 CA 未变时无需重新导入；**根 CA 一旦重建或更换，必须重新核对指纹并信任新根证书**。

### 方法一：证书信任脚本（推荐）

最简单的方式：把发布包或安装目录中的 `一键信任证书.cmd` 发给员工，双击运行即可。

- 双击：仅为当前 Windows 用户安装，不需要管理员权限；
- 右键“以管理员身份运行”：为这台电脑的所有 Windows 用户安装；
- 窗口显示“证书链验证：通过”后按任意键关闭，再完全退出并重开浏览器。

文件默认连接 `https://192.168.1.100:9443`。如果主机地址或端口变了，用记事本打开文件，修改开头的 `set "SERVER=..."` 一行，或使用新版发布包中的文件。

如果习惯命令行，或需要批量部署和排查，也可以使用下面的 PowerShell 命令：

在员工电脑上打开 PowerShell（当前用户即可，不需要管理员）：

```powershell
powershell -ExecutionPolicy Bypass -File .\trust-certificate.ps1 -Server https://192.168.1.100:9443
```

如果希望该电脑的所有 Windows 用户都信任，使用管理员 PowerShell：

```powershell
powershell -ExecutionPolicy Bypass -File .\trust-certificate.ps1 -Server https://192.168.1.100:9443 -Machine
```

脚本会：

1. 从服务器下载根证书；
2. 连接服务器，检查实际下发的服务器证书是否包含本次访问的 IP 或主机名；
3. 把根证书导入 `Cert:\CurrentUser\Root`（`-Machine` 时为 `Cert:\LocalMachine\Root`）；
4. 验证服务器证书链，并打印证书指纹和 SAN 地址。

看到“证书链验证：通过”后，**必须完全退出所有 Edge/Chrome 窗口**（包括后台进程）再重新打开。可以直接在地址栏访问 `edge://restart` 或 `chrome://restart` 重启浏览器。只刷新页面可能仍显示旧警告。

如果导入前想先检查服务器证书是否正确，可加 `-VerifyOnly`（只验证、不导入）：

```powershell
powershell -ExecutionPolicy Bypass -File .\trust-certificate.ps1 -Server https://192.168.1.100:9443 -VerifyOnly
```

### 方法二：手动导入

管理员在“管理后台 → 备份与系统 → HTTPS 证书”点击“下载客户端证书”，把 `.cer` 文件发给员工：

1. 双击 `.cer` →“安装证书”；
2. 选择“当前用户”→ 下一步；
3. 选择“将所有的证书都放入下列存储”→ 浏览 →“受信任的根证书颁发机构”；
4. 完成导入后完全退出并重开浏览器。

也可以在员工电脑执行：

```powershell
certutil -user -addstore Root .\office-files-cert.cer
```

### 核对指纹

在员工电脑导入前，与管理员后台显示的 **SHA-256 指纹**核对一致。这里显示的是根证书指纹，`trust-certificate.ps1` 打印的也是根证书指纹。不要把来源不明的证书导入受信任存储。

### 地址变化

- 主机 IP 或主机名变化：管理员应计划重启服务，在启动时检查自动服务器证书是否覆盖新地址；必要时重签，并核验新访问地址和证书 SAN。服务运行期间不会因 IP 变化自动重签。
- 若根 CA 保持不变，员工电脑继续信任原根证书，**无需重新导入**；若根 CA 因缺失、失效、临近到期等原因重建，或主动更换，则需重新执行信任脚本并核对新指纹。不要把删除 `<数据目录>\certs` 当作常规排障手段。
- 自定义外部证书由维护人员更新，不走上述自动重签流程；建议仍给主机设置固定 IP 或 DHCP 地址保留。

### 仍然显示安全警告时

1. 确认浏览器地址与脚本打印的 SAN 完全一致，例如必须是 `https://192.168.1.100:9443`，不能混用另一块网卡的 IP。
2. 完全退出所有 Edge/Chrome 窗口后重开，或访问 `edge://restart` / `chrome://restart`。
3. 用 `-VerifyOnly` 检查服务器证书是否包含当前访问地址；如果缺少，停止并重新启动服务让服务器重签证书。
4. 确认根证书在当前用户存储中：

```powershell
Get-ChildItem Cert:\CurrentUser\Root | Where-Object { $_.Subject -like "*办公室文件中心*" }
```

5. 如果使用 Firefox，需要在 Firefox 自己的证书设置中导入，Windows 证书存储对它无效。
6. 仍无法解决时，把脚本完整输出、浏览器显示的证书详情和管理员后台的指纹一起提供给维护人员。

> 若旧数据目录尚无可用根 CA，升级后首次启动会生成根证书，员工电脑需要重新导入；已有可用根 CA 时会沿用。是否需要重新信任以实际根证书指纹是否变化为准，不能只凭“升级过”判断。

### 使用企业内部证书（可选）

如果单位已有受信任的证书或内部 CA，可不使用自动证书。准备 PEM 格式证书和私钥，授予 LocalService 读取权限，然后修改服务启动参数：

```powershell
Stop-Service LanFilePlatform
icacls "D:\Certs" /grant "*S-1-5-19:(OI)(CI)RX" /T

$bin = '"C:\Program Files\LanFilePlatform\LanFileServer.exe" -data "D:\LanFileData" -addr ":9443" -tls-cert "D:\Certs\server.crt" -tls-key "D:\Certs\server.key"'
Get-CimInstance Win32_Service -Filter "Name='LanFilePlatform'" |
    Invoke-CimMethod -MethodName Change -Arguments @{ PathName = $bin }

Start-Service LanFilePlatform
```

证书必须包含员工实际访问的主机名或 IP。企业内部证书由单位 CA 签发时，员工电脑通常已信任，不需要单独导入。外部证书在启动时读取，不由系统自动续签；到期、更换或地址变化时由维护人员安排更新和重启。上例按默认服务名和 LocalService 编写，自定义部署须沿用实际参数和账号。

### 只做本机测试

临时测试可以使用明文模式：

```powershell
LanFileServer.exe -data "D:\LanFilePlatform\LanFileTest" -addr "127.0.0.1:8080" -http
```

HTTP 模式下密码和文件不加密，**不得用于正式办公室环境**。

## 5. 账号和权限

| 角色 | 全部项目 | 权限区 | 管理后台 |
|---|---|---|---|
| 主机账号 | 全部文件可见；上传、更新、改名、移动、删除、恢复 | 全部文件可见；新建文件夹、上传；管理所有权限区文件；可删除全部权限区文件、维护权限区文件夹；可见权限区回收站和审计 | 全部 |
| 管理员（非主机） | 全部文件可见；上传、更新、改名、移动、删除、恢复 | 按每个文件的可见范围；可新建文件夹、上传；可管理自己上传的权限区文件（改名、移动、更新、恢复、改可见范围）；可删除可见范围内的权限区文件，不能维护文件夹；后台不显示权限区回收站和审计 | 用户管理（不能授予管理员、不能编辑同级）、回收站、日志、设置、备份 |
| 操作员 | 全部文件可见；上传、更新、改名、移动、删除、恢复 | 按每个文件的可见范围；可新建文件夹、上传；可管理自己上传的权限区文件；可删除可见范围内的权限区文件，不能维护文件夹 | 用户管理只读；回收站（主空间）、操作日志（不含权限区）、备份与系统、系统设置可用；不能创建、编辑、重置或删除账号 |
| 编辑者 | 全部文件可见；上传、更新、改名、移动、删除、恢复 | 只能查看、下载和删除被授权的文件；不能上传或维护文件夹 | 无 |
| 只读者 | 全部文件可见；浏览、搜索、下载 | 只能查看、下载和删除被授权的文件 | 无 |

- “权限区”与“全部项目”同级，目录结构对所有登录用户可见，只有文件按可见范围隐藏。权限区不支持在“全部项目”和“权限区”之间移动节点。
- 权限区默认规则：上传者和主机账号可见，上传时角色严格高于上传者的账号可见；同级其他账号和更低角色不可见。指定可见只授权勾选的权限组或用户，不叠加等级规则。
- 权限区文件只有上传者或主机账号能修改可见范围和版本；只要文件在可见范围内，任何账号都能把它移入回收站，包括只读者。权限区文件夹仍只有主机账号能重命名、移动或删除，避免借删目录连带清除自己看不见的文件。被删除的权限区内容只出现在主机账号的回收站。
- 非主机管理员的操作日志不显示权限区条目；这是后台展示隔离，拥有主机或数据库权限的人仍可直接读取数据。备份目录包含权限区文件，应按敏感资料保护。

- 新账号首次登录会收到一次修改初始密码的建议，不再强制改密，可直接进入文件中心。
- 管理员重置密码后，该账号已有登录会失效，下次登录仍需先改密。
- 停用账号会立即使其会话失效；历史操作记录保留。
- 系统禁止停用或降级最后一个可用管理员。
- 任何账号都不能修改自己的角色或权限等级；当前账号的编辑弹窗中角色固定。
- 非主机管理员不能编辑或重置同级管理员，也不能把任何账号设为管理员；只能管理下级管理员以外的账号。普通管理员新建或编辑账号最高授予操作员。主机账号可以维护其他管理员并授予管理员角色。
- 操作员可以进入管理后台，使用回收站、操作日志、备份与系统、系统设置；用户管理只读，不能新建、编辑、重置或删除账号。主空间回收站可恢复和永久清理；权限区条目和权限区操作日志只对主机账号显示，操作员不能通过接口越权处理。操作员可修改系统设置和触发备份，请按内部职责决定是否授予。系统设置和备份接口在服务端放行操作员，账号写接口仍返回 403。
- 初始化时创建的账号标记为“主机账号”，只能由本人维护；其他管理员不能修改其资料、角色、状态，也不能重置其密码。主机账号可以编辑、重置和删除其他管理员。
- 只有主机账号可以删除其他账号；主机账号不能删除自己。删除后账号立即无法登录，但已上传文件、历史版本和操作记录会保留。若只是暂时停用，请优先使用“编辑 → 停用账号”。

## 6. 备份（必做）

历史版本保存在同一块数据盘上，**不能防止硬盘损坏、主机丢失或勒索软件**。

### 配置

1. 准备独立备份目录，例如 `E:\OfficeBackup` 或另一台电脑的共享目录。
2. 如果备份目录在本地磁盘，确保 LocalService 有写权限：

```powershell
icacls "E:\OfficeBackup" /grant "*S-1-5-19:(OI)(CI)M" /T
```

3. 管理员登录 →“系统设置”：
   - 启用每日自动备份；
   - 设置每天开始时间和保留成功备份份数；
   - 填写备份目录，保存。
4. 打开“备份与系统”，点击“立即备份”，确认出现“成功”记录。

注意：`NT AUTHORITY\LocalService` 默认不能使用带密码的网络共享。若必须备份到 NAS，建议使用本地外置硬盘，或请 IT 人员把服务改为有网络访问权限的专用本地账号。服务账号变更需重新授予数据目录和备份目录权限。

### 备份内容

每个成功备份目录包含：

```text
run-YYYYMMDD-HHMMSS/
├── meta.db          数据库一致性快照
├── manifest.json    数据库摘要和全部对象清单
├── complete.json    完成标记
├── objects/         全部版本文件内容（含回收站）
├── files/           当前版本的可读副本（原文件夹、原文件名，可直接打开）
├── README-可读副本.txt
└── certs/           自动根证书与服务器证书（ca.crt/ca.key/server.crt/server.key）
```

`files/` 是方便直接用资源管理器查看的副本，只包含**当前版本**；历史版本仍完整保存在 `objects/` 和 `meta.db` 中。为兼容 Windows，极少数与系统保留名冲突的名称会加上前缀。可读副本会额外占用约等于当前文件总量的备份空间。它只用于应急查看，完整恢复仍应使用 `-restore`。

备份通过 SQLite 在线快照创建，不是简单复制正在使用的数据库文件。每个复制对象都重新计算 SHA-256 并校验；只有全部成功才写入完成标记。失败备份不会覆盖上一份成功备份。

备份中的 `certs` 目录包含根证书私钥；泄露后可能被用来伪造受员工电脑信任的站点，必须和业务数据同等保护。

### 保留与风险

- 默认保留最近 7 份成功备份，可在系统设置调整。
- 备份目录不要放在数据目录内，系统会拒绝这种配置。
- 自动备份只在设定的那一分钟触发；如果主机当时关机，当天不会自动补做。请查看“最近成功”时间，必要时手动备份。
- 若每日备份均成功，故障时也可能丢失上次备份点以来约一天的新修改；备份失败或漏做会使损失窗口更长。**RPO（可接受的数据损失时间）须由业务确认**，再据此安排备份频率、补备和巡检，不能把“每日一次”视为达标承诺。**RTO（恢复服务所需时间）通过演练实测**，本轮没有实测成绩。重要项目可随时手动备份。
- 备份目录包含全部文件和服务器私钥，应像业务数据一样限制访问。为防止勒索软件加密备份，建议定期轮换一块离线移动硬盘。

### 恢复演练（至少每季度一次）

**禁止使用真实生产数据目录演练，也不能把临时实例指向生产数据。** 在 `D:\LanFilePlatform` 下准备独立演练目录，将选定的完整成功备份复制为演练输入；以下名称仅为示例，源目录必须实际存在、恢复目标必须为空。副本同样含业务数据和私钥，应限制访问。

```powershell
# 1. 使用已复制到独立演练区的完整备份，不操作正式备份源
$backup = "D:\LanFilePlatform\RestoreSource\run-20261118-023000"

# 2. 仅恢复，不启动实例
& "C:\Program Files\LanFilePlatform\LanFileServer.exe" -restore $backup -restore-to "D:\LanFilePlatform\RestoreCheck"
```

**首次启动前的隔离门槛（不可跳过）：** `-restore` 原样恢复数据库，`settings` 中的原 `backup_dir`、自动备份开关、时间和保留份数也会保留。换了数据目录、端口或使用 HTTP，都不会禁用计划备份；临时实例可能向正式备份目录写入，并按保留策略清理正式备份。

由授权维护人员先在副本验证方案，在**待启动的恢复副本**中禁用自动备份，并确保演练实例对原备份目录没有写入、删除权限（使用隔离环境或独立测试身份，不削减生产服务所需权限）。当前没有用于跳过计划备份的启动参数；本文不提供未经验证的 SQL。不能确认隔离有效时，到恢复步骤为止，**不要启动实例，也不要等登录后台后才处理**。如需演练备份功能，只能改用独立演练备份目标，不得复用正式目标。

隔离确认后，才单独执行：

```powershell
# 3. 仅监听本机回环；不得改为 :8444 或生产监听地址
& "C:\Program Files\LanFilePlatform\LanFileServer.exe" -data "D:\LanFilePlatform\RestoreCheck" -addr "127.0.0.1:8444" -http
```

在本机打开 `http://127.0.0.1:8444`，核对账号、目录、当前文件、历史版本和回收站；记录样本、备份点、开始/结束时间、实际恢复耗时及结果。这个 HTTP 演练不等于正式 HTTPS、服务账号或员工网络接入验收。完成后关闭临时实例，确认无进程占用，再经确认清理演练副本；不要清理生产数据或正式备份。

`-restore` 会校验数据库摘要和每个对象，不会接受未完成的备份。

### 真实故障恢复

先核对实际数据目录、服务账号和证书配置，以下按默认部署示例。恢复会回到所选备份点，由业务确认可能丢失的后续更改；不同意时先保留现场并联系维护人员。

1. 停止服务：`Stop-Service LanFilePlatform`，确认所有使用数据目录的进程退出、无占用。
2. 保留现场及故障前新增数据，不要删除旧数据。把 `D:\LanFileData` 改名为独立的现场保留目录（如 `D:\LanFileData.bad-20261118`，不得覆盖已有目录）。
3. 新建空目录 `D:\LanFileData`，用备份恢复：

```powershell
& "C:\Program Files\LanFilePlatform\LanFileServer.exe" -restore "E:\OfficeBackup\run-..." -restore-to "D:\LanFileData"
icacls "D:\LanFileData" /grant "*S-1-5-19:(OI)(CI)M" /T
```

4. 恢复成功后先核对恢复的备份设置、实际服务账号权限、证书及启动参数，再启动服务，确认账号、文件、历史和备份后恢复使用。
5. 如果恢复失败，不要继续启动或覆盖旧数据。保留恢复失败目录和原故障现场，联系技术人员决定后续方案；不要自动把疑似损坏的数据切回运行。

若使用外部证书（`-tls-cert/-tls-key`），证书文件不在数据目录中，恢复后需单独放回原路径。

## 7. 日常维护

建议按以下最低频率安排巡检，业务高峰或故障期间加密检查；判据和责任人由本单位确认：

| 频率 | 检查与判据 | 记录字段 |
|---|---|---|
| 每个工作日 | 服务运行、页面可登录；数据盘和备份盘有余量，数据盘剩余空间高于配置的保留空间并满足近期增长 | 时间、检查人、服务/登录结果、两盘余量、异常及处理人 |
| 每次计划备份后（至少每日核对） | “最近成功”时间符合业务批准的 RPO；失败、漏做或超期时排查并补备，不能只看开关已启用 | 备份点/目录、成功时间、状态、错误、补备结果 |
| 每周 | 查看 `server.log` 错误和大小、操作日志及容量趋势；日志持续增大或反复报错应安排处理，不能依赖运行中 10 MB 限额 | 日志大小、磁盘趋势、异常摘要、处理及复核时间 |
| 每月及地址/证书变更前后 | 检查证书到期和 SAN、Windows 更新、磁盘健康及供电；证书问题须在到期前安排维护重启，重启后核对指纹和访问 | 到期日、指纹是否变化、地址、维护窗口、复核结果 |
| 至少每季度及重大升级前 | 按隔离恢复流程核对账号、目录、当前/历史内容和回收站；实测恢复耗时是否满足业务要求，不预填“通过” | 程序版本、备份点、隔离确认、样本、起止时间/RTO、结果和遗留问题 |

管理员负责日常检查和员工反馈；业务负责人确认 RPO、恢复时间要求及数据损失取舍；授权维护人员负责升级、证书和副本恢复验证。验收结论按版本、日期、环境和证据记入[验收记录](验收记录.md)，维护变更同步[更新日志](更新日志.md)。内部交接资料、真实账号密码及私钥在受控位置单独保管，**不写入随包 `docs`**。
- 上传因空间不足暂停时：清理无用的回收站内容或经确认后清理历史版本，或扩容磁盘。不要手工删除 `objects` 文件。
- 回收站可在“管理后台 → 回收站”逐项永久删除，或点击“清空回收站”一键全部永久删除；两者都不可撤销，操作会记入日志。
- 员工离职：优先停用账号，不删除账号，保留历史记录；如需彻底移除误建账号，可由主机账号在用户管理中删除，历史记录仍会保留。
- 版本增长过快时：在文件详情的历史版本页，由管理员逐个清理不需要的旧版本；操作会记入日志。
- 定期检查主机 Windows 更新、磁盘健康和 UPS/供电。
- 重启主机前可在服务管理器中停止服务；服务本身支持优雅停止，正常重启不必手工操作。

## 8. 升级

### 升级前

1. 安排维护窗口，通知用户暂停写入。从最终备份到升级验证结束保持暂停，避免把未纳入备份的新修改遗漏在回滚点之外。
2. 核对并记录原程序版本、安装目录、数据目录、监听地址/端口、服务名、服务账号、证书路径、`-hosts` 及其他启动参数和备份设置；可用 `sc.exe qc LanFilePlatform` 查看默认服务配置（自定义服务名须替换）。凭据单独安全保管，不写入文档。
3. 按第 2、6 节完成并确认**升级前完整备份**，保留匹配的旧程序或旧发布包；若做数据目录冷拷贝，必须停服并确认无进程占用后完整复制。外部证书和私钥、服务参数不由平台数据备份完整涵盖，应另行受控保管。重大升级先在隔离副本验证升级与回滚。

### 推荐：使用安装入口

常规部署优先解压新包，**双击 `安装.cmd`**。数据目录和端口必须沿用原值（默认示例 `D:\LanFileData`、`9443`）；不要盲目回车。脚本会停止并删除旧服务、替换程序文件，再注册并启动服务；不删除数据目录，但新版启动会执行数据库迁移。

- 若仅自定义安装目录或服务名，使用 `install.ps1`，明确传入与原部署一致的 `-InstallDir`、`-DataDir`、`-Port`、`-ServiceName`，仍须核对交互提示。
- **脚本不会自动继承旧服务的全部配置**：它固定使用 LocalService，并只生成 `-data` 和 `-addr` 启动参数。若已有自定义服务账号、外部证书 `-tls-cert/-tls-key`、附加证书地址 `-hosts` 或其他自定义监听参数，**不要直接用默认安装入口覆盖**；应由授权维护人员采用下述手工替换方式，保留原服务配置。脚本没有这些自定义配置的对应参数，不能凭空添加。

### 高级：保留现有服务配置，手工替换程序

仅由维护人员在完成相同备份准备后执行；与上面的安装方式二选一，不重复重建服务。

1. 停止实际服务（默认示例 `Stop-Service LanFilePlatform`），确认该程序及所有使用数据目录的进程已退出。
2. 保留旧程序，用新版 `LanFileServer.exe` 替换**实际程序目录**内的对应文件，不替换数据目录，也不修改已有服务账号、证书或其他启动参数。
3. 启动原服务（默认示例 `Start-Service LanFilePlatform`）；数据库迁移会在启动时执行。失败时先保留日志和现场，不反复换程序试开数据库。

### 升级后验证

核对运行版本及全部自定义参数，用原账号登录，检查目录、当前文件、历史、权限、备份目标和成功记录，并检查证书与日志。按[部署验收清单](#11-部署验收清单)及[验收记录](验收记录.md)记录实际结果，再通知用户恢复写入；不能用历史测试代替本次验收。

0.3.0 升级后所有旧会话会失效，需提前通知员工重新登录；管理员还应确认“权限区”根节点存在，用测试账号分别验证默认/指定可见、未授权时列表与下载不可见，并确认非主机账号（管理员和操作员）看不到权限区回收站和操作日志条目。首次应用主机账号迁移时，会优先选择未停用管理员中最早创建的账号；若没有未停用管理员，则从停用管理员中选择最早创建者。升级后请在“用户管理”中确认主机账号标识，并妥善保管该账号密码。

### 回滚（不是只恢复数据库）

当前没有数据库降级迁移（down migration），也不能依赖旧程序主动拒绝新版结构。**禁止直接用旧程序打开升级后的数据库。** 0.3.0 尤其不能只换回 0.2.8 或更早 EXE：旧程序不认识权限区空间和文件 ACL，可能把权限区内容当作普通项目展示和下载。

1. 停止服务并确认无进程占用，保留新版程序、故障日志、升级后的完整数据目录及其中新数据，不覆盖故障现场。
2. 由业务负责人决定是否回滚：恢复到升级前备份点会丢失该点之后的新增、更新、删除和设置更改。保留升级后副本不等于这些更改会自动合并；需要的数据应另行评估保全方案。
3. 将**升级前同一备份点的完整数据**恢复到一个新空目录（例如 `D:\LanFileData.rollback-20261118`，须确认不存在旧内容），包括数据库、全部对象/历史和证书；不能只恢复 `meta.db` 或只用 `files` 可读副本。平台备份使用经副本验证的匹配旧版程序及其恢复流程；完整冷备则整目录恢复，不与故障目录混拷。
4. 使用与该备份点匹配的旧程序，由维护人员核对新目录权限、原服务账号、端口、证书、全部启动参数及恢复的备份设置后切换。先在隔离副本验证（遵守第 6 节首次启动隔离门槛），再安排正式切换和验收。
5. 验收通过并经业务确认后恢复使用；保留故障现场和升级后数据直到保留期限及数据取舍得到确认，不为腾空间提前删除。

## 9. 故障排查

| 现象 | 排查 |
|---|---|
| 服务无法启动 | 查看 `<数据目录>\logs\server.log`；检查端口是否被占用；确认数据目录 ACL 含实际服务账号权限（默认 LocalService）；`sc.exe query LanFilePlatform` 查看退出码，自定义服务名须替换 |
| 员工无法打开页面 | 主机是否开机；地址和端口是否正确；网络是否为专用/域；防火墙规则是否存在；从主机本机 `https://localhost:9443` 是否可用 |
| 浏览器证书警告 | 核对地址、SAN、有效期和根证书指纹；IP 变化时安排重启以检查自动证书，外部证书由维护人员处理；仅在根 CA 未信任或已变化时重新核对并导入，不要盲目删除 `certs` |
| 能打开但登录失败 | 密码错误、账号停用、连续失败被临时限速（5 分钟后重试）；非主机账号可由管理员重置，主机账号见下行 |
| 首次初始化按钮提示不能操作 | 必须从主机本机 `localhost`/`127.0.0.1` 访问 |
| 上传提示空间不足 | 检查数据盘剩余空间和“保留空间”设置；系统会保留一定空间保障服务运行 |
| 上传提示版本冲突 | 文件已被他人更新；刷新页面查看最新版本，再决定重新上传或改名 |
| 备份失败 | 备份目录不存在/无写权限/磁盘满/源文件缺失；查看备份记录中的具体消息和日志 |
| 备份显示“进行中”但服务重启过 | 启动时会把中断任务标记为失败；重新手动备份即可 |
| 下载文件 404 | 文件可能已被删除或数据对象缺失；权限区文件也可能是当前账号不在可见范围。检查回收站和日志，必要时从备份恢复 |
| 权限区能看到文件夹但看不到某些文件 | 正常现象：目录公开、文件按可见范围隐藏。联系上传者或主机账号确认默认规则/指定可见；不要通过改名或复制绕过授权 |
| 升级 0.3.0 后所有员工被退出登录 | 迁移 005 会删除会话以安全重建用户表，这是预期行为；确认服务正常后通知员工重新登录 |
| 操作员看不到新建账号或账号写按钮 | 操作员用户管理只读；回收站、操作日志、备份与系统、系统设置可用，账号维护由管理员或主机账号完成 |
| 操作员看不到权限区回收站/日志 | 预期行为：权限区条目只对主机账号显示。操作员仍可按可见范围访问权限区文件本身 |
| 忘记管理员密码 | 非主机管理员可由其他管理员重置；主机账号无自助找回入口或命令，也不能由其他管理员重置。联系授权技术人员，先在隔离副本验证恢复方案，确认后安排正式处理；禁止临时直接写生产数据库 |

## 10. 安全注意事项

- 正式环境必须使用 HTTPS；不要长期使用 `-http`。
- 每台主机和员工账号使用独立密码，不要共用管理员账号。
- 不把服务暴露到互联网；不在公用网络配置文件下开放端口。
- 默认服务使用 LocalService 运行；自定义部署沿用经批准的专用账号，数据目录权限只授予实际服务账号和必要管理员。
- 操作日志能追溯日常操作，但主机管理员可直接修改本地文件，因此不是防篡改审计系统。
- 平台不运行上传的文件内容，但不替代杀毒软件；员工下载后仍需终端安全防护。浏览器预览只允许白名单类型并禁止复用缓存，但已显示的图片、文本或已缓冲的媒体无法从浏览器内存中撤回；删除或撤权会阻止后续请求。
- 备份目录与服务器私钥应限制访问；重要环境使用离线副本防勒索软件。
- 自签名证书只适合内部使用；具有内部 CA 时优先使用 CA 签发的证书。
