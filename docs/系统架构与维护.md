# 系统架构与维护说明

本文面向后续开发和维护人员，以当前源码为依据。产品版本为 **0.4.1**；2026-11-26 已按该版本完成前端构建、Go 测试和重命名目标页验证，未现场核实正式主机。历史验收结论不自动适用于当前源码或现场环境。

## 1. 设计目标

- 十几人、一台 Windows 主机、局域网浏览器访问。
- 部署简单，不依赖 Docker、外部数据库或客户端软件。
- 文件可追溯、可恢复，误删可找回。
- 单进程、单主机，结构清晰，便于维护和扩展。
- 数据安全和备份可验证，不把“有历史版本”误当成“有备份”。

明确的非目标：本地自动同步、SVN 工作流、在线协同编辑、全文检索、分布式部署、按部门/目录继承的复杂权限。权限区只做文件级可见性，不替代完整文档管理系统。

## 2. 组件

```text
web/ (React + Ant Design + Vite)
        │ 构建到 internal/webui/dist
        ▼
internal/webui (go:embed)
        │
cmd/server ── internal/api ── internal/auth
        │            ├────── internal/files ── internal/storage
        │            ├────── internal/audit
        │            ├────── internal/settings
        │            └────── internal/backup
        ├── internal/db (SQLite WAL + 迁移)
        ├── internal/certsetup (本地根证书与服务器证书)
        └── internal/service (Windows 服务)
```

安装脚本将程序注册为 Windows 服务，账号为 `NT AUTHORITY\LocalService`；开发时也可按控制台模式运行。数据目录与程序目录分离，安装脚本不覆盖数据，但新版程序首次打开数据库可能执行迁移，不能据此认为升级无数据变更。

### 设计决策与原因 / 变更影响

| 决策与原因 | 修改时必须联动考虑 |
|---|---|
| 单 Windows 主机、单进程、SQLite WAL；减少十几人规模的部署和运维成本 | 文件写入互斥锁只在进程内有效，不能直接扩成多实例共享数据目录；更换数据库/存储要重验并发、备份与迁移 |
| 前端构建产物内嵌 EXE；分发不依赖 Node.js 运行环境 | UI 改动需重新构建内嵌资源与 EXE，并做浏览器回归，不能只改 `web/` 就宣称已更新发布包 |
| 不可变对象 + 追加版本；保留历史且便于一致性快照 | 上传、历史恢复、GC、回收站、备份必须维持引用及锁顺序，不可原地覆盖对象 |
| 基础版本 ID 乐观冲突检查；避免覆盖他人更新 | 前后端上传/恢复协议和提交时重查必须一起保留；同名预检查不能代替事务内检查 |
| 主机账号保护、用户软删除；保护管理入口和历史关联 | 账号路由、鉴权、数据库迁移及历史上传人展示一起回归，不能把软删除改成直接删除用户行 |
| 权限区采用同一节点表的逻辑空间 + 文件级 ACL；目录结构公开、避免目录继承和物理双存储 | 列表、搜索、详情、下载、历史、审计、ZIP、回收站必须统一走同一可见性判断；新增入口若漏掉 ACL 会直接泄露文件 |
| 可见范围存放在文件节点，不放在版本；改版本或恢复历史不改变授权 | 新版本、恢复、移动、改名和备份恢复都要保留 `visibility_mode` 与 `node_acl`，不能只处理当前版本内容 |
| CLI 管部署参数，数据库 settings 管业务策略 | 改目录、端口、服务身份、证书或默认值时，要同时检查安装脚本、后台文案、备份恢复和管理员指南 |

## 3. 数据布局

```text
<data>/
├── meta.db           SQLite 数据库，WAL 模式
├── objects/ab/<id>   不可变文件内容，按 ID 前两位分目录
├── tmp/              上传临时文件
├── certs/            自动生成的根证书与服务器证书
└── logs/             服务日志
```

对象路径只由服务端生成的随机 ID 决定，不使用用户提供的路径。节点名用于显示、逻辑目录、下载响应头及 ZIP/备份可读副本的路径，不作为对象存储路径；名称校验和可读副本名称处理不能省略。

### 配置来源与部署记录

| 来源 | 当前参数/设置及默认值 |
|---|---|
| CLI（`cmd/server/main.go`、`internal/config/config.go`） | `-data data`、`-addr :9443`、`-http false`、`-hosts`（逗号分隔附加 SAN）；`-tls-cert` 与 `-tls-key` 必须成对提供；`-restore` 与 `-restore-to` 为独立恢复模式，`-version` 输出程序版本 |
| 安装脚本（`installer/install.ps1`） | 默认安装到 `%ProgramFiles%\LanFilePlatform`，数据目录 `D:\LanFileData`，端口 9443；服务启动参数显式记录数据目录及地址；与 CLI 的相对目录默认值不同 |
| SQLite `settings`（初值见 `001_init.sql`） | `site_name=办公室文件中心`、`max_file_size_bytes=2147483648`、`free_space_reserve_bytes=5368709120`、`recycle_retention_days=30`、`backup_enabled=true`、`backup_time=02:30`、`backup_keep=7`、`backup_dir=''` |

后台通过 `GET/PUT /api/admin/settings` 读写业务策略；JSON 的 `max_file_size`、`free_space_reserve` 对应数据库的两个 `*_bytes` 键。CLI 参数和 Windows 服务配置不会保存在该表，不能只靠数据库备份还原部署环境。`recycle_retention_days` 即使为 30，也只是保存/显示建议保留天数，**没有按天自动清空回收站的实现**；备份目录默认空，启用计划不等于已有可用备份。

维护交付必须记录实际程序/数据/独立备份目录、监听地址/端口、服务名称与 `LocalService` 身份及访问权限、外部证书/私钥路径与续期责任、附加 SAN 和防火墙范围；不要在文档中保存私钥或口令。备份程序只复制 `<data>/certs` 中约定的四个自动证书文件，不会追踪 CLI 指定的外部证书路径。权限及部署操作见[管理员部署指南](管理员部署指南.md)，不要为测试更改正式服务身份或权限。

开发明文实例必须显式 `-addr 127.0.0.1:8080 -http`；`-http` 不会自动收紧监听地址。数据使用 `D:\LanFilePlatform` 下独立开发目录，不能指向正式数据。

## 4. 数据库模型

| 表 | 作用 |
|---|---|
| `users` | 账号、Argon2id 密码摘要、角色、主机账号标识、强制改密、首次登录建议标记（`first_login`）、停用、软删除标记 |
| `sessions` | 会话令牌的 SHA-256、过期时间 |
| `nodes` | 文件/文件夹节点、父目录、当前版本、修订号、软删除批次；`space` 区分 `main`/`secure`，`created_by_id` 记录上传者，`secure_owner_role` 记录上传时角色，`visibility_mode` 为 `default`/`custom` |
| `node_acl` | 权限区文件的指定可见范围：`principal_type` 为 `role` 或 `user`，`principal_id` 为角色码或用户 ID；默认规则不写 ACL 行 |
| `versions` | 版本号、对象 ID、大小、SHA-256、上传人、说明 |
| `objects` | 不可变内容对象目录 |
| `audit` | 操作日志快照（操作人、对象名称/路径、结果、IP）；`secure` 标记权限区条目，非主机管理员查询时隐藏 |
| `settings` | 平台名称、大小限制、保留空间、备份策略 |
| `upload_tasks` | 上传幂等结果、pending/completed/failed 状态；不保存分片或续传偏移 |
| `backup_runs` | 备份执行历史 |
| `schema_migrations` | 已应用迁移的文件名与时间（不记录 SQL 内容哈希） |

关键约束：

- 同一空间、同一父目录下活动名称唯一，由 `(space, parent_id, name)` 的 `COLLATE NOCASE` 部分唯一索引保证；主空间与权限区可以存在同名节点，这是 SQLite NOCASE 语义，不是完整 Unicode 大小写折叠。
- 权限区根节点是 `space='secure' AND parent_id='' AND kind='folder'` 的唯一固定节点，由迁移创建；目前没有删除或重建后台入口。
- `node_acl` 只对权限区文件生效；权限区文件夹不读 ACL，所有登录用户都能看到目录结构。
- `versions(node_id, version_no)` 唯一。
- 节点删除采用 `deleted_at + delete_batch`，不立即物理删除。
- 审计记录保存当时的显示名称和路径，不依赖后续改名。
- 文件重命名只修改主文件名，扩展名必须与原名称完全一致；服务端对文件返回 `EXTENSION_IMMUTABLE`，文件夹不受此限制。前端把后缀作为只读片段展示，不放进可编辑输入框。

### 迁移与兼容边界

当前迁移位于 `internal/db/migrations/`：

| 文件 | 实际作用 |
|---|---|
| `001_init.sql` | 建立初始业务表、索引及 settings 初值 |
| `002_owner.sql` | 增加 `users.is_owner`；按 `disabled ASC, created_at ASC, id ASC` 从管理员中选一个回填主机账号（有启用账号时优先启用账号），并建立唯一部分索引 |
| `003_user_delete.sql` | 增加 `users.deleted_at`（空字符串表示未删除）及索引 |
| `004_first_login.sql` | 增加 `users.first_login`（新建账号首次登录建议标记，默认 0；首次登录提示后或修改密码时清除） |
| `005_operator_role.sql` | 重建 `users` 表，CHECK 允许 `operator`；SQLite 重建期间删除并重建 `sessions`，因此**所有已登录会话失效**。同一迁移不重新建立登录，升级后需要重新登录 |
| `006_secure_zone.sql` | 增加节点空间、上传者、上传时角色、可见性模式和 `node_acl`；重建按空间隔离的名称唯一索引；给审计增加安全标记；插入固定“权限区”根节点 |

**0.3.0 回滚特别说明**：0.2.8 及更早程序不会读取 `space`、`node_acl`，会把权限区根节点当作普通项目，权限区文件可能对未授权账号显示和下载。升级后不能只替换旧 EXE；回滚必须恢复升级前同一备份点的完整数据，并保留升级后的现场副本。

`db.Open` 在启动时运行迁移：内嵌 SQL 文件按**文件名排序**，以 `schema_migrations.name` 判断是否应用过，每个未应用文件的 SQL 和登记行放在同一个事务中提交；不是所有迁移共用一个大事务，后续失败不会撤销此前已成功迁移。已登记的名字直接跳过，不比较内容哈希。

后续 schema 变更只能追加新编号迁移，**不得改写已应用的旧 SQL**。当前没有降级脚本，也没有“旧程序检测到新 schema 必定拒绝启动”的保护；禁止用旧程序直接试开升级后的正式数据库。早期 0.1 阶段曾使用相同版本号，版本号相同不能证明 schema 或源码相同；兼容表必须按具体包/EXE 哈希、迁移清单和具体数据副本验证，不能仅按 `0.1 → 0.2` 推定兼容。

升级前保存完整备份及匹配旧包。回滚恢复的是**同一备份点的数据库、对象、自动证书和相应部署记录**，而不只是换 EXE 或恢复单个 `meta.db`；外部证书单独保全。实际演练和切换步骤见[管理员部署指南](管理员部署指南.md)。

## 5. 核心写入规则

以下为维护时必须保持的不变量：对象写成后不可变；上传先落盘后提交元数据；同名及基础版本在提交时重查；历史恢复追加版本而非改写历史；清理不能删除仍被任一版本引用的共享对象。账号软删除及主机账号约束见第 6 节。这些是服务逻辑和数据库约束共同维护的规则，不代表文件系统与 SQLite 存在跨介质原子事务。

### 上传新文件

1. API 先检查权限、名称、父目录、同名冲突和磁盘空间。
2. 请求体流式写入 `tmp/`，同时计算 SHA-256，超过上限立即失败；不把整个文件读入内存。
3. 文件 `fsync` 后移动到 `objects/`，成为不可变对象。
4. 开启 SQLite 事务：
   - 再次检查父目录和同名；
   - 插入 node（先插入，避免版本外键指向不存在的节点）；
   - 插入 object 和 version；
   - 写审计；
   - 提交。
5. API 对上传提交报错会立即尝试删除此次新对象，并标记任务失败；崩溃或删除失败留下的孤儿再由 GC 延迟清理。不能把临时任务状态当成数据库与文件写入的跨事务保证。

### 上传新版本

- 请求必须携带基础的当前版本 ID。
- 在进程内写锁和事务内重新读取节点，若当前版本已改变，返回 `VERSION_CONFLICT`，不静默覆盖。
- 新版本号 = 节点修订号 + 1；更新唯一当前版本指针。

单进程使用互斥锁串行化会改变目录/版本状态的提交操作。SQLite 本身也会串行化写入。

### 历史恢复

- 校验基础版本后，为新版本记录复用原对象（对象不可变），新增版本行并更新当前指针。
- 不删除后来的版本，也不会破坏已有历史。

### 删除与回收站

- 使用递归 CTE 把节点和所有活动子节点标记为同一个删除批次。
- 普通用户不访问回收站；管理员恢复时检查原父目录和名称冲突。
- 永久清理先持有文件服务互斥锁和 `Store.Guard` **写锁**，在数据库事务内删除版本/节点并重查对象引用；仅把无引用对象列入删除清单，提交后再尝试删除磁盘内容。文件删除失败留下孤儿，由 GC 后续尝试清理。
- 清理单个历史版本时禁止删除当前版本，并检查对象是否仍被其他版本引用；恢复历史可能让多个版本共享同一对象，不能按“一个版本一个对象”直接删除。
- 回收站仅由管理员手工按批次或全部永久清理；`recycle_retention_days` 没有自动清理消费者。

### 文件系统与数据库一致性

两者不能组成同一个事务，系统选择：

- **允许孤儿对象**，不允许已提交版本引用缺失对象；
- 上传先落盘后提交；
- 清理对象前检查引用；
- 启动时及此后每隔 24 小时运行维护，清理超过约 24 小时的上传临时文件和无版本引用的孤立对象（删除前再查引用），不是固定每天零点任务；并清理过期会话，将超 1 天的 pending 上传标为失败、删除超 90 天的 completed 及超 30 天的 failed 任务。这里不包含回收站定时清空。

## 6. 认证与权限

- 密码：6～128 个字符，Argon2id（64 MB、3 次、2 线程），盐和参数编码在摘要中。
- 会话：32 字节随机令牌，Cookie 仅保存令牌，数据库保存 SHA-256；HttpOnly、SameSite=Lax，HTTPS 下 Secure。
- 登录失败限速：同一用户名 + IP 10 分钟内 5 次失败后锁定 5 分钟。
- 修改请求拒绝 `Sec-Fetch-Site: cross-site`，有 `Origin` 时比较其 Host 与请求 Host；缺少这两个头并不会仅因此拒绝。响应设置 CSP、nosniff、禁止 iframe，不能把这些措施视为完整安全审计。
- 角色在服务端每个请求重新从数据库读取，停用账号立即失效。
- 常规角色从高到低为管理员 > 操作员 > 编辑者 > 只读者，`model.RoleRank` 提供排序；主机账号的 `EffectiveRank` 高于全部常规角色。管理员、操作员、编辑者可编辑主空间；管理员和操作员可进入管理后台及上传权限区。
- 用户管理层级：任何账号不能修改自己的角色；非主机管理员不能编辑或重置同级管理员，只能维护更低角色的账号；主机账号可以维护其他管理员。只有主机账号可授予或保留管理员角色；普通管理员新建或编辑账号时最高只能设为操作员。操作员可进入后台并使用回收站、操作日志、备份与系统、系统设置，但用户管理只读：不能创建、编辑、重置或删除账号。主空间回收站对操作员开放恢复和永久清理；权限区条目仍隐藏。校验按目标账号当前角色和操作者 `is_owner` 在服务端执行，前端隐藏入口只是辅助。
- 初始化账号带 `is_owner` 标记（唯一），固定为管理员且不能停用、降级或删除；只能由本人维护，其他管理员修改或重置密码会被服务端拒绝。常规账号更新还保护最后一个启用管理员，禁止停用当前登录账号。
- 权限区使用逻辑空间，不从父目录继承授权。所有登录用户都能看到权限区文件夹和目录结构；文件是否可见由文件自身的 `visibility_mode` 和 `node_acl` 决定。主机账号（`IsOwner`）和上传者始终可见。
- `visibility_mode='default'`：按节点记录的 `secure_owner_role` 计算，角色严格高于上传时角色、但又不是上传者的账号可见；同级其他账号和更低角色不可见。上传者角色以后变化不自动重算。
- `visibility_mode='custom'`：只有勾选的角色组成员或具体用户可见；不叠加默认等级规则。至少选择一个角色或用户；停用、删除或不存在的用户不能作为新授权对象。
- 未授权的权限区文件在列表、搜索、详情、版本、下载、预览、面包屑、节点审计和文件夹 ZIP 中都按不存在处理（通常返回 404）；管理后台的全局审计和回收站仅对主机账号显示权限区条目。
- 浏览器预览走独立只读端点，先按文件 ACL 和时间点重新解析当前版本，再从对象存储读取；不复制到公开静态目录。每次请求（包括媒体 Range 分段请求）都重新校验登录、删除状态和可见性，因此删除或撤权后的旧链接不能继续读取。后端只接受明确白名单扩展名并设置固定 `Content-Type`、`X-Content-Type-Options: nosniff` 和 `Cache-Control: private, no-store, max-age=0`；文本统一按 `text/plain; charset=utf-8` 输出，HTML、SVG 和 Office 等不在白名单内。文本最多读取 1 MiB，按 UTF-8 优先、GB18030 回退转换后交给前端 `<pre>` 展示，不执行上传内容。
- 权限区管理：操作员及以上可新建文件夹和上传；权限区文件夹只有主机账号可改名、移动、删除；权限区文件可由上传者或主机改名、移动、更新版本、恢复历史和修改可见范围；文件只要对当前账号可见，就可以软删除（移入回收站），包括只读者，服务端在删除时重新按可见范围校验；权限区根节点不可改名、移动或删除。禁止跨空间移动。
- 删除账号采用软删除：写入 `deleted_at`、设为停用、删除会话，用户名追加 `#deleted-<id>` 释放原名；用户行及显示名称保留用于历史版本关联。只有主机账号可以删除其他账号，不能删除自己或主机账号；重新创建同名账号会生成新 ID，不继承旧身份。
- 首次初始化只允许回环地址访问，且仅在没有任何用户时可用。

## 7. 备份设计

备份不是复制数据库文件。流程：

1. 获取存储 `RWMutex` 读锁，阻止永久清理删除被备份引用的对象。
2. 使用 `VACUUM INTO` 生成一致的数据库快照。
3. 从快照读取全部版本引用的对象清单。
4. 逐对象复制并计算 SHA-256，复制大小和摘要必须与清单一致。
5. 复制自动生成的根证书和服务器证书（`ca.crt`、`ca.key`、`server.crt`、`server.key`，如存在）。
6. 按快照中的目录树把当前版本复制到 `files/`，生成可直接浏览的可读副本；历史版本仍只保存在 `objects/`。
7. 写入 `manifest.json`、`complete.json` 和可读副本说明。
8. 写回数据库备份记录为成功。快照、复制、校验或标记写入失败时通常会尝试删除不完整目录；若最后写回数据库记录失败，完成标记可能已存在，目录不会在该分支删除。不能只看目录存在就当作本次成功，应核对记录、日志、清单及实际恢复结果。
9. 成功后按保留份数清理旧备份：识别 `run-*` 目录内 `complete.json` 的应用标记并按目录修改时间排序；不会在清理时重新校验全部对象，删除错误也不保证呈现在备份成功结果中。

恢复命令 `-restore` 检查清单应用标识和完成标记存在，目标必须为空或不存在；先校验数据库摘要并复制，再逐对象边复制边校验大小/SHA-256，最后复制自动证书。不是“全部校验通过后一次性原子恢复”，失败可能留下部分目标文件；不能把失败目标直接当成可启动数据目录。自动证书只复制，没有与对象同等的清单摘要校验。

### 自动调度与恢复边界

`StartScheduler` 每 30 秒检查一次，以服务器本地时间的 `HH:MM` 严格匹配 `backup_time`（默认 02:30）；启用开关关闭或已有备份运行时跳过。错过匹配分钟不会补做，也不是启动后立即补备份。

`lastAttemptAt` 是内存中的日期字符串：调度命中后、启动备份 goroutine 前就设置为当天，因此同一进程内计划尝试失败也不会当天自动重试。它不从 `backup_runs` 恢复，进程重启后清空；若仍在计划分钟内可能再次尝试，不能声称重启后仍保证同日去重。手动备份不更新该字段。启动时 `RecoverInterrupted` 只把残留 running 记录改为 failed，不恢复中断任务。

恢复副本会继承数据库中的备份 settings；首次运行前的隔离与设置处理，统一遵循[管理员部署指南](管理员部署指南.md)的恢复演练步骤，不能让演练实例操作原备份目标。

RPO 由成功备份的间隔决定，默认每日计划不等于保证 24 小时内必有恢复点；RTO 取决于数据量和介质，应通过演练测量。

## 8. HTTP API 摘要

以 `internal/api/server.go` 的路由和对应 handler/service 校验为准。下表标记：P = 无需登录，U = 已登录，E = 管理员/操作员/编辑者，A = 管理员，S = 管理员/操作员，O = 主机账号。管理员重置密码后的强制改密状态下，除 `me/logout/change-password` 外，所有需登录接口均拒绝访问；新账号首次登录不再拦截，只返回一次修改建议标记。所有写请求仍经过同源校验。标记只是路由入口要求；权限区节点还会按文件 ACL、上传者、主机账号和空间规则进一步校验，未授权文件按不存在处理。

`/api/health` 只返回进程内信息，没有检查数据库、对象完整性或备份可恢复性，不能单凭 200 判定系统健康。证书接口只提供公钥证书，未启用 HTTPS 时返回不存在。

关键请求字段（查询参数须 URL 编码，JSON 请求使用 `application/json`）：

| 请求 | 字段及含义 |
|---|---|
| `GET /api/nodes/resolve` | 查询 `parent`（根目录为空）、`name`；只做预检查，仍需处理随后上传/建目录时的冲突 |
| `POST /api/nodes` | JSON `parent_id`（根目录为空）、`name`；只创建文件夹 |
| `PUT /api/upload`（新文件） | 查询 `upload_id`、`parent`、`name`，可选 `note`；权限区可带 `visibility_mode`（`default`/`custom`）、`visibility_roles`、`visibility_users`（逗号分隔）。请求体为完整原始文件字节 |
| `PUT /api/upload`（新版本） | 查询 `upload_id`、`node`（文件 ID）、`base`（观察到的当前版本 ID），可选 `note`；有 `node` 时以已有节点为目标，不靠 `parent/name` 重命名；权限区新版本沿用原可见范围 |
| `PUT /api/nodes/{id}/visibility` | JSON `mode`（`default`/`custom`）、`roles`（角色码数组）、`users`（用户 ID 数组）；`custom` 至少选择一项 |
| `POST /api/nodes/{id}/restore-version` | JSON `version_id`（要恢复的历史版本）、`base_version_id`（当前基础版本）；恢复后新增版本 |
| `POST /api/recycle/{batch}/restore` | 批次来自回收站返回的 `delete_batch`，不需要 JSON；原父目录和同名冲突仍须通过检查 |

`upload_id` 限 8～64 位字母、数字、下划线或短横线；同一账号重复提交已完成 ID 返回原结果（`duplicate: true`），pending 返回 `UPLOAD_IN_PROGRESS`，failed 可重试，不能拿旧 ID 上传另一份内容。任务记录不提供断点续传，状态和文件提交也不是同一事务。文件夹上传由前端创建/复用目录，再逐文件调用这些接口，空文件夹不上传；不是整文件夹原子提交，也没有额外的文件夹上传端点。

统一错误格式：

```json
{"error":{"code":"VERSION_CONFLICT","message":"文件已被他人更新，请刷新后重试"}}
```

主要错误码：`INVALID_NAME`、`NAME_EXISTS`、`CROSS_SPACE_MOVE`、`VERSION_CONFLICT`、`UPLOAD_IN_PROGRESS`、`FILE_TOO_LARGE`、`NO_SPACE`、`PASSWORD_CHANGE_REQUIRED`、`FORBIDDEN`、`ADMIN_ASSIGN_FORBIDDEN`、`SAME_LEVEL`、`SELF_ROLE`、`INVALID_VISIBILITY`、`EMPTY_VISIBILITY`、`NOT_SECURE_FILE`。未授权的权限区文件通常返回 404，而不是暴露其存在的 403。

## 10. 运行维护：证书与日志

### 证书检查发生在启动时

`cmd/server/main.go` 仅在启动且未指定外部证书的 HTTPS 模式调用 `certsetup.Ensure`，没有定时续签或运行中热重载：

- CA 为 ECDSA P-256，生成时有效期 10 年；仅当可读取证书/私钥、为 CA、密钥匹配且到期时间严格晚于“现在 + 1 个日历年”时复用。剩余期限 **≤1 年** 或检查失败会重新生成 CA。
- 服务器 leaf 生成时有效期 2 年；检查可读、密钥匹配、由当前 CA 签名、到期时间严格晚于“现在 + 30 天”，并覆盖当前收集的主机名/IP 与 `-hosts`。剩余期限 **≤30 天**、SAN 缺失或其他检查失败时重签。
- IP/主机名变化要在下一次启动检查才生效；若 CA 仍满足复用条件，仅重签 leaf 不要求重新信任根证书。CA 被更换后必须核对新指纹并重新分发信任，不能承诺永远只信任一次。
- 外部 `-tls-cert/-tls-key` 不由自动生成逻辑续签，维护人员负责更新及重启验证。自动模式后台证书摘要/到期字段取自 **CA**，SAN 取自 leaf；后台显示根证书未过期不能替代 leaf 到期检查。

### 服务日志不是实时限额轮转

`internal/logging/logging.go` 将日志追加到 `<data>/logs/server.log`，并同时输出 stderr（先写文件），包含日期时间和微秒。只在启动 `Setup` 时检查已有文件是否 **大于 10 MiB**：删除 `.3`、`.2 → .3`、`.1 → .2`、当前文件 `→ .1`，再打开新的 `server.log`。运行中不会按大小或日期轮转，长时间运行可超过阈值；轮转删除/改名错误被忽略，因此不能保证始终只有三份归档或磁盘占用受限。服务日志与数据库 `audit` 是不同记录，均不能防主机管理员篡改。巡检、保全与清理操作见管理员指南，不直接删业务对象。

3. 版本保留策略按数量/容量自动执行（需与备份保护协调）。
4. 文件签出锁，降低“基于旧版本编辑”的冲突概率。

不建议在十几人规模下拆分微服务或引入分布式对象存储；当前单机方案维护成本更低，实际容量边界仍需测试。

## 12. 已知限制

- 通过 Cookie 的写请求防护依赖同源校验和 SameSite，若将来在前面加反向代理，必须确保 Host/Origin 正确。
- 审计记录不防主机管理员篡改。
- 备份目录如果与数据目录在同一块物理硬盘，无法抵御硬盘损坏。
- 自动备份不补做错过的计划分钟；同日尝试去重仅在内存中，详见第 7 节。
- 搜索只匹配名称，最多返回 200 条。
- 自动证书仅在启动时检查；CA 更换需重新信任，不支持 Firefox 自动配置，详见第 10 节。
- 新上传不按内容摘要去重；历史恢复会复用对象，不能据此假设所有版本内容都独占一个对象。
- 回收站保留天数不是自动清理开关；空间须通过管理员确认后手工清理。
- 权限区只过滤文件，目录结构对所有登录用户可见；权限不继承、不按组织架构计算，新增文件需要重新选择可见范围。可见范围按上传时角色计算默认规则，之后调整角色不会自动重算已有文件。
- 非主机管理员的权限区回收站条目和全局审计被隐藏；这是展示层隔离，不是数据库级不可见，直接读数据库仍能看到所有记录。
